### 什麼是 SAT 問題？
(1) 布林滿足問題（簡稱 SAT） 是一長串由 AND、OR、NOT 拼出來的邏輯式子，是歷史上第一個被嚴格證明為 NP-Complete（NP 完全） 的問題（Cook-Levin 定理）。
(2) 核心目標：給每個變數挑 True 或 False，讓整串式子的最終結果變成 True，就是給定一組由布林變數（Boolean Variables）構成的邏輯運算式，判斷是否存在一種真假值組合（Assignment），使得整個式子的計算結果為 True，如果只用暴力法窮舉 $n$ 個變數，時間複雜度是慘烈的 $O(2^n)$。而 DPLL 就是在暴力嘗試之前，先用邏輯推理把能確定的變數直接釘死，大幅減少白做工的次數
(3) 判定結果：
* SATISFIABLE (SAT)：至少存在一種指派方式使公式為真。
* UNSATISFIABLE (UNSAT)：無論變數如何指派，公式必然矛盾，永遠為假。
(4) 在現代求解器中，公式通常被標準化為合取範式（CNF）直接沿用國際標準 DIMACS 的整數編碼法：
(5) 變數與文字：用數字代表。正數是原變數，負數代表加上 NOT。1 $\rightarrow x_1$-2 $\rightarrow \neg x_2$子句（Clause）：一串用 OR 連接的文字，用 Python List 放。[1, -2] 代表 $(x_1 \lor \neg x_2)$整份公式：所有子句用 AND 綁在一起。[[1, 2], [-1, 3]] 代表 $(x_1 \lor x_2) \land (\neg x_1 \lor x_3)$
* 整個公式是由多個子句（Clause）用「且（AND, $\land$）」相連。每個子句內部則是由多個文字（Literal）用「或（OR, $\lor$）」相連。

### 程式模組與演算法架構
DPLL 本質上是帶有確定性剪枝規則的深度優先搜尋（DFS）。主要由五個部分構成：

1. simplify(formula, literal)（公式簡化）
當某文字被設為 True 時，包含該文字的子句直接滿足並移除；包含其相反文字的子句則剃除該相反項。若過程中出現空子句（Empty Clause），代表產生邏輯衝突，此路徑失敗。當我們設定某個變數（例如令 $x_1 = \text{True}$）：
- 子句有 $x_1$，那條子句直接滿足，丟掉不用看了。
- 子句有 $-x_1$（False），從子句裡剔除。
- 地雷點：如果某個子句裡的東西被踢光了變成 []（空子句），代表搞出矛盾了，這條路行不通，立刻收工回溯

2. find_unit_literal(formula)（單文字傳播）
若某子句只剩唯一文字（長度為 1），為了成立整個公式，必須是 True。這個動作常會引發骨牌效應，一路連續解開好幾個變數。

3. find_pure_literal(formula)（純文字消除）
若某文字在所有剩餘子句中只以同一極性（全正或全負）出現，將其直接設真，絕不影響其他子句

4. dpll (二元分支猜測)
推理都是過了了還是沒解開？那就挑一個變數開始猜：先猜它 True 看看能不能走通；不行就掉頭回溯改試 False。兩個都死路就代表無解。

### 測試
1. 測試 1：一般可滿足公式（驗證單文字傳播的級聯效應）
* 測資：formula1 = [[1, 2], [-1, 3]]（即 $(x_1 \lor x_2) \land (\neg x_1 \lor x_3)$）
* 程式碼：
```
print("--- 測試 1：(x1 or x2) and (not x1 or x3) [預期：可滿足 SAT] ---")
formula1 = [
    [1, 2],
    [-1, 3]
]
solve_sat(formula1)
```
* 輸出
```
--- 測試 1：(x1 or x2) and (not x1 or x3) [預期：可滿足 SAT] ---
狀態: SATISFIABLE (可滿足)
變數賦值解: {'x1': True, 'x2': True, 'x3': True}
```
* 學習:
  * 推論的連鎖反應：一開始先試了 $x_1 = \text{True}$，第二個子句裡的 -1 就被砍掉，瞬間讓它縮成只剩 [3] 的單文字子句，進而直接逼出 $x_3 = \text{True}$。
  * 自由變數：其實第一式因為 $x_1$ 是 True 早就被滿足了，$x_2$ 根本隨便設都可以。這讓我意識到 SAT 往往不是只有唯一解，我們只要能撈出一組活路就算過關。

2. 測試 2：矛盾式與邊界條件

* 程式碼：
```
print("--- 測試 2：(x1) and (not x1) [預期：不可滿足 UNSAT] ---")
formula2 = [
    [1],
    [-1]
]
solve_sat(formula2)
```
* 輸出
```
--- 測試 2：(x1) and (not x1) [預期：不可滿足 UNSAT] ---
狀態: UNSATISFIABLE (不可滿足)
```
* 學習:
  搞懂空子句：一開始寫 code 時差點把子句被清空跟公式被清空搞混。後來看懂了：公式清空 [] 代表全滿足；但子句被剃成 [] 則是代表這條式子無論如何都不可能為 True（直接判死刑）。這就是 DFS 回溯能剪枝的關鍵哨兵。


3. 測試 3：三變數子句（3-SAT）

* 程式碼：
測資：formula2 = [[1], [-1]]（即 $(x_1) \land (\neg x_1)$）
```
print("--- 測試 3：(x1 or not x2 or x3) and (not x1 or x2 or x4) and (not x3 or not x4) [預期：可滿足 SAT] ---")
formula3 = [
    [1, -2, 3],
    [-1, 2, 4],
    [-3, -4]
]
solve_sat(formula3)
```
* 輸出
```
--- 測試 3：(x1 or not x2 or x3) and (not x1 or x2 or x4) and (not x3 or not x4) [預期：可滿足 SAT] ---
狀態: SATISFIABLE (可滿足)
變數賦值解: {'x1': True, 'x2': True, 'x3': True, 'x4': False}
```
* 學習:
  搜尋樹的膨脹：子句變長之後，一開始完全沒有單文字可以當突破口，這時候演算法就會被迫進入猜測模式。
  Heuristic 的重要性：如果公式更大、變數更多，如果挑中一個到處都有出現的關鍵變數，猜下去產生的連鎖反應會強得多，搜尋樹也會瞬間縮減。
