### 什麼是 $2^n$ 計算問題與演算法複雜度？
1. 計算 $2^n$ 是演算法設計中最基礎且極具代表性的遞迴與動態規劃範例 ，此問題表面上僅為乘冪計算，但採用不同實作方式（直接運算、單遞迴、雙遞迴、記憶化查表）會導致時間複雜度從 $O(1)$ 暴增到 $O(2^n)$ 的極端差異
2. 核心目標：
    透過計算 $2^n$ 觀察遞迴呼叫樹（Recursion Tree）的展開過程，深入探討「重疊子問題（Overlapping Subproblems）」對程式執行效能的毀滅性影響，以及動態規劃（Dynamic Programming / Memoization）與傳統代數運算的優化機制
3. 判定結果：
    * SUCCESS（秒殺回傳）：時間複雜度落在 $O(1)$ 或 $O(n)$，在 $n = 100$ 的規模下皆能在千分之一秒以內瞬間完成
    * HANG / TIME_OUT（程式卡死 / 時間爆炸）：未加修剪的雙遞迴使得呼叫次數呈指數增長，運算次數高達 $O(2^n)$，在有限時間內根本無法完成運算
4. 遞迴關係與數學表：
    * 基本遞迴關係式：$2^n = 2 \times 2^{n-1}$ 或 $2^n = 2^{n-1} + 2^{n-1}$，終止條件為 $2^0 = 1$。
    * 雙遞迴時間複雜度推導：
    $$T(n) = 2T(n-1) + O(1) \implies T(n) = O(2^n)$$
5. 關鍵特色（原地更新）：
    * 雙遞迴：呼叫樹每往下一層節點數就翻倍，極其嚴重的重複計算子問題（例如計算 $2^{98}$ 會被重複呼叫無數次）
    * 記憶化查表：算過的值即刻存進雜湊表中，後續查詢只要 $O(1)$，直接將龐大的指數級呼叫樹剪枝為線性鏈條

### 程式模組與演算法架構
高斯-賽德爾求解器主要由四個模組組成：

1. power2n_1(n)（方法 1：內建運算符直接計算）
利用 Python 內部底層優化的大數快速冪（Fast Exponentiation）演算法直接求值 $2^n$。時間複雜度接近 $O(1)$（大數乘法複雜度可視為對數級），為效能基準
2. power2n_2b(n)（方法 2b：線性單遞迴）
採用 $2^n = 2 \times 2^{n-1}$ 關係式。每層只發起單一次遞迴呼叫，展開長度為 $n$ 的單鏈，時間複雜度為 $O(n)$，空間複雜度（呼叫堆疊）為 $O(n)$

3. power2n_3(n, memo=None)（方法 3：雙遞迴加記憶化查表）
計算關係式為 $2^n = 2^{n-1} + 2^{n-1}$，但透過引入字典 memo 保存已經算過的子問題解。遇到重複狀態直接查表回傳，將時間複雜度大幅壓制回 $O(n)$

4. power2n_2a(n)（方法 2a：純雙遞迴，無查表）
未加快取的二元遞迴展開，形成一棵滿二元樹（Full Binary Tree）。每個節點均重複計算左右子節點，時間複雜度為爆炸性的 $O(2^n)$

### 測試
1. 測試 1：$n = 100$
* 程式碼：
```python
t0 = time.perf_counter()
ans1 = power2n_1(100)
t1 = time.perf_counter()
print(f"方法 1 耗時: {t1 - t0:.8f} 秒")
```

* 輸出：
```
方法 1 耗時: 0.00000210 秒

```
* 學習:
    - 極限效能：Python 內建的 ** 運算符採用 C 語言層級的二進位快速平方法，耗時近乎為零，是日常程式開發的最佳解。

2. 測試 2：方法 2b 單遞迴 vs 方法 3 查表雙遞迴
* 程式碼：
```
# 方法 2b 單遞迴
t0 = time.perf_counter()
ans2b = power2n_2b(100)
t1 = time.perf_counter()
print(f"方法 2b 耗時: {t1 - t0:.8f} 秒")

# 方法 3 記憶化查表
t0 = time.perf_counter()
ans3 = power2n_3(100)
t1 = time.perf_counter()
print(f"方法 3 耗時: {t1 - t0:.8f} 秒")
```

* 輸出：
```
方法 2b 耗時: 0.00003450 秒
方法 3 耗時: 0.00008620 秒
```
* 學習:
    - 剪枝的奇蹟：方法 3 雖然使用了拆分成兩份的遞迴結構，但因為查表機制的介入，將原先天文數字般的呼叫次數強行壓縮到僅需計算 100 個獨立狀態，成功在萬分之一秒內完成。

    - 額外開銷：方法 3 比方法 2b 稍慢一點點，主因是字典的雜湊查表與多餘函式呼叫的常數時間消耗。

3. 測試 3：方法 2a 雙遞迴卡死測試
* 測資：第一式對角項為 0（即 $0x_1 + 2x_2 = 4$）
* 程式碼：
```
print("\n--- 正在測試方法 2a ---")
print("說明：因為計算量高達 2^101 次運算，程式將卡死在此處以證明『出不來』...")

```

* 輸出：
```

說明：因為計算量高達 2^101 次運算，程式將卡死在此處以證明『出不來』...
(程式進入無止盡的樹狀計算迴圈，終端機停滯無回應，需按 Ctrl + C 強制終止)
```
* 學習:
    - 演算法結構的毀滅性：即便現代 CPU 時脈極高，也敵不過 $O(2^n)$ 的指數級膨脹。這充分證明了動態規劃（查表法）在消除重疊子問題時所帶來的決定性效能提升。
